# ADR-0029 step 5 -- the protocol for the falsification sweep of P1-P3

Frozen before the first sweep launch. `docs/prereg/ADR-0029.step5.PREREG_SHA256.txt` records the
hash of this file and of `tools/cu_sweep.py`, which implements it, and the commit they were frozen
at. The predictions are ADR-0029's P1-P3, frozen at `docs/prereg/ADR-0029.prereg-frozen.md`, and
are not repeated or edited here. This file fixes what the ADR left open, the same way ADR-0028's
step-5 protocol did, and reuses its instruments unchanged.

## What is measured

* **The control.** `examples/cu.lyth` at `-n 2097152`: sixteen contiguous buffers of 2^21 f32
  (8 MB each), the body of `cu_q` byte for byte, no split.
* **The split kernel.** `examples/cu_q.lyth` at `-n 8388608` (four buffers of 2^23 f32, 32 MB each,
  2^21 quads), for every ordered pair `(c, t)` with `c, t ∈ {0, 1, 2, 3, 4, 8, 16, 22}`, `c ≠ t`:
  56 configurations. Widths `wc = 2^c`, `wt = 2^t` if `t < c` else `2^(t-1)`.
* Both move 64 B per quad by the compiler's model, walk 2^21 quads and touch 128 MB, past the 34 MB
  L2. Both take the same unitary, `--set ar=0.6 ai=0.1 br=0.2 bi=0.7 cr=0.3 ci=0.5 dr=0.6 di=0.4`
  (the values do not change a byte or a flop; they are fixed so every run is the same program).
* One binary (`target/release/lyth.exe` at the recorded commit), `fixtures/machine/sm_120.json`.
  The sweep refuses a dirty tree.

## Instruments (ADR-0028 step 5's, unchanged)

* **Bytes:** `ncu` on the one launch `lyth run` makes without `--time`, default cache control, 3
  launches per configuration in 3 rounds shuffled by `random.Random(29)`, median per counter:
  `lts__t_bytes.sum`, `dram__bytes_op_read.sum`, `dram__bytes_op_write.sum`, over 2^21 quads.
* **The derived isolated figure** is read from the same `lyth run` output, its `exact ... byte per
  quad` line.
* **Time:** `lyth run --time 200 --json`, one process per sample, 7 rounds, each round all 57
  configurations in a fresh order from the same generator; a configuration's time is the median of
  its 7 process medians, its spread `(max - min) / median` of those 7.

## Verdicts, fixed now

`tol = 5%`, `eps = max(tol, control's spread)`, `r(c,t) = lts(c,t) / lts(control)`,
`T(c,t) = t(c,t) / t(control)`.

* **P1:** PASS if DRAM bytes per quad (read + write) are within `tol` of the control's at every
  `(c, t)`.
* **P2:** three parts, each published.
  * **equal where every run fills a sector:** `|r - 1| <= tol` for every `(c, t)` with `min(c, t) >= 3`;
  * **bounded everywhere:** `r <= 1.10` at every `(c, t)`;
  * **the derived figure is an upper bound:** `derived(c, t) >= lts(c, t) / (1 + tol)` at every
    `(c, t)` (the tolerance is for counter noise where both are 64).
* **P3:** PASS if `|T - 1| <= eps` at every `(c, t)`.
* **P4 at this size:** every `lyth run` in the sweep prints `BIT-EXACT`.

## What was seen before this was frozen

One `lyth run` of the control at `-n 2097152` and one of `cu_q` at `(c, t) = (3, 2)`, to see the
harness accept sixteen buffers and a depth-2 split at size: both BIT-EXACT, the latter printing an
isolated figure of 128 B per quad. No timing, no counters.
