# ADR-0029, P2 follow-up -- where the L1-to-L2 excess of a two-qubit gate goes

Frozen before the measurement. Hashes of this file and of `tools/p2_followup.py` are in
`docs/prereg/ADR-0029.p2-followup.PREREG_SHA256.txt`. This is the measurement ADR-0029's step-5
notes named after P2's 1.10 bound was falsified. It predicts; it does not re-judge P2.

## What was seen before freezing (disclosed, because it shapes F1)

* **One `ncu` probe** of `cu_q` at `(c, t) = (0, 1)`, `-n 1048576` (fits in L2): L2 read sectors
  262,843 for 262,144 quads (one per quad, the payload's), L2 write sectors 610,049 (2.33 per quad),
  and 75% of global-load sectors hit in L1. So at that size the excess was in writes. F1 asks
  whether that holds at the sweep's size and across the classes of `(c, t)`.
* **The SASS of `cu_q` and `cu_q_grouped`** (`ptxas -arch=sm_120`): `ptxas` reorders the stores --
  the copies, ready first, are stored first -- so the order in which drained streams are declared
  does not fix the order of `STG` instructions. F3 is therefore a question about the declaration,
  not a controlled test of store order.

## What is measured

`ncu`, default cache control, 3 launches per configuration in shuffled rounds (`random.Random(290)`),
median per counter, divided by 2^21 quads, at the sweep's size (`-n 8388608`; the control `cu` at
`-n 2097152`), the sweep's unitary:

`lts__t_bytes.sum`, `lts__t_sectors_op_read.sum`, `lts__t_sectors_op_write.sum`,
`l1tex__t_sectors_pipe_lsu_mem_global_op_ld.sum`, `..._op_ld_lookup_hit.sum`,
`l1tex__t_sectors_pipe_lsu_mem_global_op_st.sum`.

Configurations: the control, and `cu_q` and `cu_q_grouped` (the same kernel with the drained
streams declared `re` leaves first, then `im`) at `(c, t)` in
`(0,1) (1,0) (0,2) (2,0) (0,3) (3,0) (0,8) (8,0) (4,1) (1,4) (22,2) (8,4)`: 25 configurations,
covering every class of the step-5 table and a pair with no narrow qubit.

## Predictions and verdicts, fixed now (`tol = 5%`)

* **F1 -- the excess is in the writes.** For `cu_q` at every `(c, t)`: L2 read sectors per quad
  within `tol` of the control's, and write sectors carry at least 90% of the L2 excess over the
  control (`(write - write_ctl) / (total - total_ctl) >= 0.9`, judged only where the total excess
  is above `tol`).
* **F2 -- the L1 serves the partner on reads.** L1 hit fraction of global-load sectors at least
  50% wherever `min(c, t) < 3`, and at most 10% at `(8, 4)`, where no two leaves share a sector.
* **F3 -- declaration order does not move the bus.** `cu_q_grouped`'s L2 bytes per quad within
  `tol` of `cu_q`'s at every `(c, t)`. Predicted to pass because `ptxas` schedules the stores itself.

Exploratory, no verdict: write sectors per quad against the isolated derived write figure.
